§1Typing and OOP in neural networks

A PyTorch model is a class that inherits from nn.Module. Layers are created in __init__ (PyTorch registers them as parameters automatically) and the computation is written in forward. Type hints such as x: torch.Tensor and docstrings document the shapes, which is what keeps a large project readable.

cell 5SimpleNN: one hidden layer

The network computes h = ReLU(xWᵀ + b), applies dropout to h, then z = hUᵀ + c. The output z holds the logits, the raw class scores. Softmax would turn them into probabilities, but nn.CrossEntropyLoss does that internally, so the model returns logits. predict switches to eval mode and uses torch.no_grad() so that no dropout is applied and no graph is built.

class SimpleNN(nn.Module):
    """A simple neural network with configurable architecture."""

    def __init__(self, input_size: int, hidden_size: int, output_size: int, dropout_rate: float = 0.2):
        """
        Initialize the neural network.

        Args:
            input_size: Number of input features (d in the slides)
            hidden_size: Number of neurons in hidden layer (d_h)
            output_size: Number of output classes (K)

        """

        self.dropout = nn.Dropout(dropout_rate)
        self.U = nn.Linear(hidden_size, output_size)

            x: Input tensor of shape [batch_size, input_size]

        """

        h = self.dropout(h)
        z = self.U(h)           # scores z (logits)
        return z

§2torch.no_grad() and train/eval modes

Two separate switches control a model. model.train() and model.eval() change how some layers behave (dropout, batch norm). torch.no_grad() changes whether PyTorch records operations for backpropagation. They are independent, so inference normally uses both.

cell 12–13Dropout in train and eval mode

In training mode dropout zeroes each hidden unit with probability p and multiplies the survivors by 1/(1−p) so the expected activation stays the same. Two forward passes on the same input therefore differ. In eval mode dropout does nothing, so the output is deterministic. The notebook prints the summed difference between two passes: positive in train mode, exactly 0 in eval mode. The requires_grad flag is True for outputs computed with gradients on and False inside no_grad().

cell 15Task 2: memory with and without gradients

compare_memory runs one forward pass over a batch of 10,000 examples twice, once normally and once inside torch.no_grad(), and returns the memory used by each. On a GPU it uses torch.cuda.max_memory_allocated; on a CPU it falls back to tracemalloc. With gradients on, PyTorch keeps every intermediate activation and the graph so that backward() can use them. Under no_grad() they are freed immediately.

Why the graph costs memory

Activations that must stay alive for backprop (filled) versus freed straight away (outlined)

When to use which

Use gradients while training, because backprop needs them to update the weights. Use torch.no_grad() together with model.eval() for validation, testing and inference, where nothing is updated: it saves memory, runs faster, and prevents accidental updates.

batch = torch.randn(10000, input_size)  # Large batch

def compare_memory(model: nn.Module, batch: torch.Tensor) -> Dict[str, int]:
    """Return the memory (in bytes) used by one forward pass of batch, with and without gradient calculation."""
    if torch.cuda.is_available():
        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()
        base_mem = torch.cuda.memory_allocated()
        _ = model(batch)
        mem_with = torch.cuda.max_memory_allocated() - base_mem

        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()
        base_mem = torch.cuda.memory_allocated()
        with torch.no_grad():
            _ = model(batch)
        mem_without = torch.cuda.max_memory_allocated() - base_mem

        return {"with_gradients": mem_with, "without_gradients": mem_without}
    else:
        # Fallback for CPU memory tracking using tracemalloc
        tracemalloc.start()
        _ = model(batch)
        _, peak_with = tracemalloc.get_traced_memory()
        tracemalloc.stop()

§4Regularization and activation functions

AdvancedNN (cell 23) builds a network of any depth from nn.ModuleLists and adds the tools that keep a bigger model trainable. Each hidden layer is Linear → BatchNorm → activation → Dropout, the last layer is a plain Linear, and an optional weight constraint caps the size of the weights after each optimizer step.

Activation functions

Without a non-linearity, stacked linear layers collapse into one linear map. Sigmoid and tanh squash values into a range but have tiny gradients for large inputs (they saturate). ReLU is max(0, x): cheap and non-saturating for positive inputs, but it outputs exactly zero (and no gradient) for negative ones. Leaky ReLU keeps a small slope there, and SiLU and GELU are smooth versions that dip slightly below zero.

Activation functions

The six options the activation argument accepts. Toggle curves; the second chart shows their gradients.

Batch normalization

For each hidden unit, BatchNorm1d standardizes the values across the batch (mean 0, variance 1) and then applies a learned scale and shift. This keeps the inputs of the next layer in a stable range, which allows larger learning rates. In training it uses the current batch's statistics, so it needs more than one example per batch; in eval mode it uses running averages collected during training.

One hidden unit before and after BatchNorm

Activations of one unit over a batch of 512, drawn from a shifted, stretched distribution

Weight constraint (max-norm)

apply_weight_constraint looks at each row of a weight matrix (all the weights into one neuron), and if its L2 norm exceeds weight_constraint it scales the row down to exactly that norm. Rows already below the limit are left unchanged. It must run after optimizer.step(), not inside forward, because it modifies the weights.

class AdvancedNN(nn.Module):
    """Neural network with various regularization techniques and activation functions.

    In the slides' notation, layer l holds W^[l] and b^[l].
    """

    def __init__(
        self,
        input_size: int,
        hidden_sizes: List[int],
        output_size: int,
        dropout_rate: float = 0.2,
        activation: str = "relu",
        use_batch_norm: bool = True,
        weight_constraint: Optional[float] = None
    ):
        """
        Initialize the advanced neural network.

        Args:
            input_size: Number of input features (d)
            hidden_sizes: List of hidden layer sizes
            output_size: Number of output classes (K)
            dropout_rate: Dropout probability
            activation: Activation function name ('sigmoid', 'tanh', 'relu', 'leaky_relu', 'silu', 'gelu')
            use_batch_norm: Whether to use batch normalization
            weight_constraint: Maximum norm for weight constraint (L2 norm)
        """
        super(AdvancedNN, self).__init__()

        self.layers = nn.ModuleList()
        self.batch_norms = nn.ModuleList()
        self.dropouts = nn.ModuleList()
        self.weight_constraint = weight_constraint

        # Input layer
        self.layers.append(nn.Linear(input_size, hidden_sizes[0]))
        if use_batch_norm:
            self.batch_norms.append(nn.BatchNorm1d(hidden_sizes[0]))
        self.dropouts.append(nn.Dropout(dropout_rate))

        # Hidden layers
        for i in range(len(hidden_sizes) - 1):
            self.layers.append(nn.Linear(hidden_sizes[i], hidden_sizes[i+1]))
            if use_batch_norm:
                self.batch_norms.append(nn.BatchNorm1d(hidden_sizes[i+1]))
            self.dropouts.append(nn.Dropout(dropout_rate))

        # Output layer (no batch norm, activation or dropout)
        self.layers.append(nn.Linear(hidden_sizes[-1], output_size))

        # Activation function
        if activation == "sigmoid":
            self.activation = torch.sigmoid
        elif activation == "tanh":
            self.activation = torch.tanh
        elif activation == "relu":
            self.activation = F.relu
        elif activation == "leaky_relu":
            self.activation = F.leaky_relu

§7Train, validation and test splits

split_dataset (cell 32) splits twice with train_test_split. First 15% goes to the test set, then 15% of the original data (0.15 / 0.85 of what remains) goes to validation. Both splits are stratified, so the share of positive reviews is the same in each. The vocabulary is then fitted on the training texts only and shared with the other two, so nothing about validation or test leaks into the features.

  • Training data fits the weights.
  • Validation data is used to choose settings and the best epoch.
  • Test data is kept for one final, unbiased estimate.

Why fit the vectorizer on train only

A word seen only in validation would get a column if the vectorizer saw all data. With train-only fitting it is simply ignored, as at deployment time.

def split_dataset(
    dataset: TextDataset,
    val_size: float = 0.15,
    test_size: float = 0.15,
    random_state: int = 42
) -> Tuple[TextDataset, TextDataset, TextDataset]:
    """
    Split a dataset into train, validation, and test sets.

    Args:
        dataset: The original dataset
        val_size: Proportion for validation
        test_size: Proportion for testing
        random_state: Random seed for reproducibility

    Returns:
        Tuple of (train_dataset, val_dataset, test_dataset)
    """
    # First split into train+val and test
    texts_train_val, texts_test, labels_train_val, labels_test = train_test_split(
        dataset.texts, dataset.labels, test_size=test_size, random_state=random_state,
        stratify=dataset.labels
    )

    # Then split train+val into train and val
    adjusted_val_size = val_size / (1 - test_size)
    texts_train, texts_val, labels_train, labels_val = train_test_split(
        texts_train_val, labels_train_val, test_size=adjusted_val_size, random_state=random_state,
        stratify=labels_train_val
    )

    # Create one dataset per split (the vocabulary is fitted afterwards, on train only)
    train_dataset = TextDataset(texts_train, labels_train)
    val_dataset = TextDataset(texts_val, labels_val)
    test_dataset = TextDataset(texts_test, labels_test)

    return train_dataset, val_dataset, test_dataset

§8Embeddings as input: mean-pooled GloVe

Bag-of-words treats "good" and "excellent" as unrelated columns. GloVe (glove-wiki-gigaword-100) gives every word a 100-dimensional vector learned from co-occurrence statistics, so words used in similar contexts get similar vectors. A review becomes the mean of its word vectors, one fixed-size vector whatever the length:

x = mean(e(w₁), …, e(wₙ)) → h = σ(xW + b) → z = hU → ŷ = softmax(z)

cell 37Task 3: embed_corpus

For each text: tokenize with clean_tokens, look up the vector of every token that exists in GloVe, and average them with np.mean(..., axis=0). If no token is known (an empty review, say) the row is a zero vector. The result is a float32 tensor of shape [m, 100]. The test checks shape (3, 100) and that the empty text gives zeros.

Show the Task 3 code
def embed_corpus(texts: List[str]) -> torch.Tensor:
    """Mean-pool the GloVe vectors of each text. Returns a float32 tensor of shape [len(texts) × glove.vector_size]."""
    dim = glove.vector_size
    results = []
    for text in texts:
        tokens = clean_tokens(text)
        vectors = [glove[t] for t in tokens if t in glove]
        if vectors:
            results.append(np.mean(vectors, axis=0))
        else:
            results.append(np.zeros(dim, dtype=np.float32))
    return torch.tensor(np.array(results), dtype=torch.float32)

§9Loss functions and optimization

Cross-entropy and softmax

nn.CrossEntropyLoss takes the scores z (logits), not probabilities. It applies log-softmax itself, which is more numerically stable, and returns −log ŷ[true class] averaged over the batch. A confident correct prediction costs almost nothing; a confident wrong one costs a lot.

Softmax and loss, live

Set the two logits and the true class.

Adam versus plain gradient descent

Gradient descent steps along the negative gradient with one learning rate for every parameter. Adam keeps a running average of each parameter's gradient and of its squared gradient, and scales the step per parameter, so directions with steep, noisy gradients take smaller steps than flat ones. weight_decay adds a small penalty on large weights.

§10The embedding matrix as a layer

In §8 the pooling happened outside the network, with GloVe frozen by construction. Here the embedding matrix E (one row per vocabulary word) becomes the network's first layer. A review is now a list of word indices; nn.Embedding looks up the rows, the network pools them, and, if freeze=False, gradients can update E itself.

cell 56Task 7: make_loaders

A DataLoader turns a list of examples into mini-batches. The training loader uses shuffle=True so every epoch sees the batches in a different order (a seeded torch.Generator keeps that reproducible), and all three loaders use collate_fn=pad_batch so each batch is padded to its own longest review. def make_loaders(train_items, val_items, test_items, batch_size: int) -> Tuple[DataLoader, DataLoader, DataLoader]:
    """Return (train_loader, val_loader, test_loader). Only the training data is shuffled."""
    generator = torch.Generator().manual_seed(42)   # makes the shuffling reproducible

    train_loader = DataLoader(train_items, batch_size=batch_size, shuffle=True, collate_fn=pad_batch, generator=generator)
    val_loader = DataLoader(val_items, batch_size=batch_size, shuffle=False, collate_fn=pad_batch)
    test_loader = DataLoader(test_items, batch_size=batch_size, shuffle=False, collate_fn=pad_batch)

    return train_loader, val_loader, test_loader

cell 60Task 8: mean pooling inside the network

EmbeddingClassifier stores E as nn.Embedding.from_pretrained(E, freeze=freeze, padding_idx=0). The two missing methods are:

  • pool: look up self.E(indices), giving [B, L, d]. Build a mask that is 1 where the index is not 0. Multiply, sum over the length axis, and divide by the number of real tokens (clamped to at least 1, so an all-padding row gives zeros instead of dividing by 0).
  • forward: pool, then W, ReLU, dropout and U, exactly as in SimpleNN, returning logits.
        embedded = self.E(indices)                                   # [B × L × d]: one row of E per token
        mask = (indices != 0).unsqueeze(-1).to(embedded.dtype)       # [B × L × 1]: 1 for real tokens, 0 for padding
        summed = (embedded * mask).sum(dim=1)                        # [B × d]: padding contributes nothing
        counts = mask.sum(dim=1).clamp(min=1)                        # [B × 1]: number of real tokens (never 0, so an empty review gives a zero vector)
        return summed / counts

    def forward(self, indices: torch.Tensor) -> torch.Tensor:
        """Return the scores z, shape [B × output_size]."""
        x = self.pool(indices)          # mean-pooled review vector x
        h = F.relu(self.W(x))           # hidden layer h
        h = self.dropout(h)
        return self.U(h)                # scores z (logits)

Why the mask matters

Mean of one review padded to different lengths. A plain mean over all positions shrinks toward zero; the masked mean does not change.

    """Accuracy of model on every batch of loader (eval mode, no gradients)."""
    model.eval()
    correct, count = 0, 0
    with torch.no_grad():
        for x, y in loader:
            x, y = x.to(device), y.to(device)
            correct += (model(x).argmax(dim=1) == y).sum().item()
            count += len(y)
    return correct / count

cell 72Task 10: learning rate scheduling

A scheduler changes the learning rate during training: large steps early to make progress fast, smaller steps later to settle into a minimum. The solution extends train_model into train_model_scheduled with an optional scheduler and records the learning rate used in every epoch in a ScheduledTrainingResult (a subclass of TrainingResult with one extra field). It supports three strategies:

  • StepLR: multiply the rate by 0.5 every 30 epochs.
  • CosineAnnealingLR: follow half a cosine from the start rate down to about 0 over all epochs.
  • ReduceLROnPlateau: halve the rate when the validation loss has not improved for 10 epochs. It is the only one whose step needs the metric: scheduler.step(val_loss).

The scheduler is stepped once per epoch after optimizer.step(). Early stopping is effectively disabled (patience 150) so that every run shows its full learning-rate curve. The model is the §9 SimpleNN on pooled GloVe features, starting at learning rate 0.01 for 150 epochs.

# Task 10: Modify the train_model function to include a learning rate scheduler

@dataclass
class ScheduledTrainingResult(TrainingResult):
    """TrainingResult plus the learning rate used in every epoch."""
    learning_rates: List[float]


def make_scheduler(optimizer: optim.Optimizer, name: Optional[str], epochs: int):
    """Build the requested scheduler; None means a constant learning rate."""
    if name is None:
        return None
    if name == "step":        # multiply the learning rate by 0.5 every 30 epochs
        return optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.5)
    if name == "cosine":      # follow half a cosine from lr down to ~0 over all epochs
        return optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=epochs)
    if name == "plateau":     # halve the learning rate when the validation loss stops improving for 10 epochs
        return optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode="min", factor=0.5, patience=10)
    raise ValueError(f"Unknown scheduler: {name}")


def train_model_scheduled(model, X_train, y_train, X_val, y_val, config: TrainingConfig,
                          scheduler_name: Optional[str] = None) -> ScheduledTrainingResult:
    """train_model with an optional learning rate scheduler; records the learning rate of every epoch."""
    device = torch.device(config.device)
    model = model.to(device)
    X_train, y_train, X_val, y_val = X_train.to(device), y_train.to(device), X_val.to(device), y_val.to(device)

    criterion = nn.CrossEntropyLoss()
    optimizer = optim.Adam(model.parameters(), lr=config.learning_rate, weight_decay=config.weight_decay)
    scheduler = make_scheduler(optimizer, scheduler_name, config.epochs)

    history = {"train_losses": [], "val_losses": [], "train_accuracies": [], "val_accuracies": []}
    learning_rates = []
    best_val_accuracy, best_epoch, patience_counter = 0.0, 0, 0
    best_state = copy.deepcopy(model.state_dict())
    start_time = datetime.now()

    for epoch in range(config.epochs):
        learning_rates.append(optimizer.param_groups[0]["lr"])   # the rate used for this epoch's update

        model.train()
        outputs = model(X_train)
        loss = criterion(outputs, y_train)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        train_acc = (outputs.argmax(dim=1) == y_train).float().mean().item()

        model.eval()
        with torch.no_grad():
            val_outputs = model(X_val)
            val_loss = criterion(val_outputs, y_val).item()
            val_acc = (val_outputs.argmax(dim=1) == y_val).float().mean().item()

        # Scheduler step goes after the optimizer step; ReduceLROnPlateau needs the metric it watches
        if scheduler is not None:
            if scheduler_name == "plateau":
                scheduler.step(val_loss)
            else:
                scheduler.step()

        for key, value in zip(history, (loss.item(), val_loss, train_acc, val_acc)):
            history[key].append(value)

        if val_acc > best_val_accuracy:
            best_val_accuracy, best_epoch, patience_counter = val_acc, epoch, 0
            best_state = copy.deepcopy(model.state_dict())
        else:
            patience_counter += 1
        if patience_counter >= config.early_stopping_patience:
            break

Self-assessment answers


  1. train() vs eval(): train() keeps dropout on and batch norm on batch statistics; eval() turns dropout off and uses running statistics, so outputs are deterministic.
  2. Why no_grad(): No graph or stored activations: less memory, faster, and no accidental weight updates.
  3. Data classes: Little boilerplate, validation in __post_init__, and configs that print, compare and serialize cleanly.
  4. Reproducibility: Fix all seeds, fix the splits, save configs and metrics, record library versions.
  5. Splits: Train fits the weights, validation picks settings, and the untouched test set gives an unbiased final estimate.
  6. Mean pooling: It loses word order ("loved X, hated Y" equals the reverse); a feedforward net can keep some by concatenating the vectors of a fixed-length window, or a sequence model (RNN, transformer) can read the order.
